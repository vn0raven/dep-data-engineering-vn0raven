# Seven-minute Observatory demo

1. **0:00–0:50 · Introduce the problem.** Route records and maps can disagree about which line represents a route direction. The Observatory gives planners a way to explore documented lines and gives data stewards a way to record what evidence is still needed. Open the M5 analysis link to show the prior work.
2. **0:50–1:35 · Explain the pipeline.** Show the local release pointer and run the release verifier. Explain checksums, SQLite checks, and the separation between passing map features and unresolved direction matches.
3. **1:35–2:50 · Explore the public map.** Open the synthetic demonstration. Filter down to bus and IRIP, then click a line to inspect its source record. Drag a rectangle across a line and read the intersection result. Draw a second rectangle that misses it.
4. **2:50–3:45 · Demonstrate a browser-local review.** Open an unresolved case, select “Request evidence,” and describe the evidence needed. Save and refresh the page, reopen the case and confirm the note is still visible. Point out the browser-local label.
5. **3:45–5:35 · Demonstrate the private workflow.** In a private session using an ignored scratch database, select a documented line tied to an unresolved case. Show the case, direction, source file and geometry status. Save a project decision. Restart the app with the same database and reopen the case to show the saved note, reviewer, timestamp and release reference. For an external recording, use the public demonstration and share the aggregate QA counts in place of private screens or notes.
6. **5:35–6:25 · Show verification.** Walk through a successful test run. Explain the rejected invalid bounds, tampered release check, and append-only history tests.
7. **6:25–7:00 · Close with deployment scope.** Show the verified Pages URL when available and what the static demo contains. Explain which additional evidence would be needed to use the workflow for current service or boarding decisions.
